= proto-mcp-pam

== What this project does

`proto-mcp-pam` is a single-binary, zero-dependency Privileged Access Management (PAM) reverse proxy for Model Context Protocol (MCP) servers written in Go.

It sit between an AI agent or MCP client and an upstream MCP server and enforce the following rules at the protocol layer:

* Intercept JSON-RPC 2.0 tool calls, especially `tools/call`
* Apply a declarative policy before any call reaches the upstream server
* Deny destructive or unauthorized operations immediately with a standard JSON-RPC error
* Allow only the minimum required privilege for a specific call
* Inject a short-lived credential or token only for that call and scrub it immediately after completion
* Emit structured JSON audit logs for accountability and forensics

AI-agent may call MCP servers with broad permissions and static secrets are a dangerous blast radius.

== Core design

The project follows a simple zero-standing-privilege model:

1. An incoming `tools/call` message is inspected.
2. Policy evaluation checks `params.name` and `params.arguments`.
3. If the call is denied, the proxy returns a JSON-RPC error immediately.
4. If allowed, the proxy injects a short-lived scoped credential or token into the upstream request path.
5. The token is removed as soon as the request completes.
6. An immutable audit record is emitted with timestamp, agent identity, tool name, hash of arguments, decision, and latency.

== Why the protocol-layer model is necessary

For AI use cases, the real security boundary is not just “who is logged in” but “what tool is being invoked and with which arguments”.

A static API key or database password can be catastrophic because:

* the agent has no per-tool least-privilege boundary
* the credential remains usable beyond a single action
* long-lived secrets often exist in multiple runtime locations
* many autonomous agents bypass centralized human-session controls entirely

`proto-mcp-pam` narrows the issue to a single tool call and enforces a policy decision before the upstream system sees the request.

== Architecture overview

[source,mermaid]
----
sequenceDiagram
    participant Agent as AI Agent / MCP Client
    participant PAM as proto-mcp-pam
    participant Policy as Policy Engine
    participant Token as TokenProvider
    participant MCP as Upstream MCP Server

    Agent->>PAM: tools/call { name, arguments }
    PAM->>Policy: Evaluate method + arguments
    alt Denied
        Policy-->>PAM: DENY
        PAM-->>Agent: JSON-RPC Error -32001: Access Denied by PAM Policy
    else Allowed
        Policy-->>PAM: ALLOW
        PAM->>Token: Issue short-lived scoped credential
        Token-->>PAM: ephemeral token
        PAM->>MCP: Forward request + injected credential
        MCP-->>PAM: Response
        PAM->>PAM: Scrub token from memory
        PAM-->>Agent: Response
    end
----

== Policy model

The project uses a declarative policy layer with example rules such as:

* allow safe read-only queries with `SELECT`
* deny destructive operations such as `DROP`, `DELETE`, or shell commands like `rm -rf`
* deny requests against unauthorized AWS or database resources
* reject tool names and arguments that exceed a defined execution boundary

This pattern aligns with least-privilege and zero standing privilege, but at the MCP protocol layer rather than at the operating system or network layer.

== Current benchmark intent

The benchmark is not intended to compete with enterprise-scale PAM suites that include full session recording and legacy system integration; it is intended to prove that a low-overhead protocol broker can fit into high-frequency AI tool execution workflows.

== Deployment model

`proto-mcp-pam` is designed as a lightweight inline broker that can be deployed as:

* a local gateway in front of a private MCP server
* a per-agent security proxy in a developer environment or CI/CD automation
* a front-end to a controlled internal MCP fleet
* a policy enforcement boundary in an enterprise AI platform

It stays intentionally small and dependency-free so it can be embedded into automation or deployed as a single process in constrained environments.

== Security posture

The core security principles are:

* zero standing privilege
* least privilege by tool and argument
* no long-lived static agent secrets
* per-call token injection
* immediate token scrubbing after completion
* explicit deny decisions before upstream execution
* structured auditability

This is specifically aligned to the failure mode of autonomous systems: broad access with narrow task execution.

== Status

This repository is a design-and-implementation prototype for a protocol-aware PAM layer. It is intended to demonstrate a solution for MCP security, especially in multi-tool and agentic environments where static credentials and broad trust boundaries are unsafe.

== Recommended use

Use `proto-mcp-pam` when:

* you have MCP servers that execute privileged operations
* you want to constrain AI agents by tool and argument, not just by network or VM access
* you want every request to leave a clear audit trail
* you want to avoid embedding persistent secrets in agent environments

It is best viewed as a complementary control to existing enterprise security programs, not as a complete replacement for broader identity, network, and secrets controls.

== Quick orientation

To build and run the prototype locally:

[source,bash]
----
go build ./cmd/mcp-pam
./demo/run_demo.sh
----

The demo is intended to show:

* an allowed read-only tool call succeeds with temporary credential injection
* a destructive tool call is blocked immediately
* audit logs are emitted in JSON and remain readable for live demonstrations

== Summary

`proto-mcp-pam` is the MCP-native equivalent of a policy-controlled credential broker: it treats tool calls as privileged actions, denies unsafe operations before execution, injects short-lived credentials only when permitted, and leaves a traceable, structured audit record.

It is not a replacement for full enterprise PAM; it fills the gap that modern AI-agent toolchains create at the protocol layer: the gap between identity and machine-executed command intent.
